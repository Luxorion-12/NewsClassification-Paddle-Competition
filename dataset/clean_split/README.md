# 去重后的本地评测数据

由 `dataset/train.txt` 和 `dataset/dev.txt` 生成。原始文件及官方无标签 `dataset/test.txt` 均不修改。

## 处理规则

1. 按标题原文及标签统计重复记录。同标题同标签只保留一条。
2. 同一标题若对应多个标签，暂不纳入这次实验：删除该标题的全部记录。共有 677 个冲突标题，涉及 1,474 条原始记录。
3. 对剩余的 787,072 个不同标题按类别分别打乱，再依照官方文件的数量比例划分：训练 82.14121%、验证 8.73296%、测试 9.12583%。随机种子为 2026。逐类四舍五入会带来约 1 条的总数差异。

| 文件 | 条数 | 格式 |
| --- | ---: | --- |
| `train.txt` | 646,510 | `标题<TAB>标签` |
| `dev.txt` | 68,736 | `标题<TAB>标签` |
| `test.txt` | 71,826 | 仅标题，供模型预测 |
| `test_labeled.txt` | 71,826 | 与 `test.txt` 同顺序，供本地评分 |

三个子集的标题互不重合，每个子集内部也没有完全相同的标题。各类别前后数量见 `class_counts.csv`，详细统计见 `report.json`。原始 832,471 条有标签记录中，按“标题＋标签”计有 44,045 条额外重复记录；该数字与冲突标题涉及的记录存在交叉，不能直接相加。

从项目根目录重新生成：

```powershell
python dataset/build_clean_split.py
```

训练只使用 `train.txt`；用 `dev.txt` 选择模型和超参数；确定方案后，按 `test.txt` 顺序输出预测并与 `test_labeled.txt` 比较 Accuracy 和 Macro-F1。之前用原数据训练出的模型已经见过新测试集中的部分标题，不能用来报告这份新测试集的成绩，需要按新划分重新训练。

本地测试统一使用 `dataset/evaluate_test.py` 评分。它会检查预测文件的行数和标题顺序，并把分类报告及混淆矩阵写入与预测文件同目录的 `test_metrics.json`。具体命令见 `dataset/BASELINE_HANDOFF.md`。
